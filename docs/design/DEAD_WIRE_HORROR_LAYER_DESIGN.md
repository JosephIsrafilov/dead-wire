## 1. Что это за документ

Хоррор-слой поверх M1-петли: как «психологический хоррор» превращается из философии GDD §20
в конкретные системы, контент и контракты. Всё построено из существующих механизмов:
scheduler, sounder, transcript paper, writer rig, dispatch ledger, window, session state machine.

Референсы-ДНК (исследование 2026-09-20, вики-разборы):

| Источник | Что взято |
|---|---|
| FNAF | каркас смены: ночь-как-смена, внимание-как-ресурс, уязвимость в момент проверки, эскалация ночей 1→6 |
| Papers, Please | усложняющиеся директивы, мелкая ошибка = цитация не смерть, игрок-винтик, драма в документах |
| Iron Lung | реальность только через посредника (наш провод/лента), существо в зазоре наблюдений, fake gauges |
| The Mortuary Assistant | рутина + прерывание; рабочий продукт игрока как счётчик ужаса (Post-It → ledger) |
| Mouthwashing | игрок управляет лжецом (рука Элиаса), PSX-дефицит как двигатель воображения |
| Killer Frequency | последствие-через-провод (ответы на твои ошибки приходят по линии), не спешить с финалом |

Главная находка исследования: у нас уже есть сильнейший псих-хоррор-механизм жанра —
**ненадёжная рука** (игрок слышит одно, его рука пишет другое). Всё строится вокруг неё,
не вокруг монстра.

## 2. Understanding Lock (подтверждён)

- **Строим:** хоррор-слой: 6 ночей + день, две нити страха (рука/психика + провод/внешняя угроза),
  лентопишущий регистр как несокрушимый якорь истины, воскресный суд на линии в реальном времени.
- **Для кого:** игрок, который хочет тяжёлый психологический хоррор без экшена.
- **Ограничения:** GDD не нарушается — слои сигнала не схлопываются, audio fairness, sparse horror,
  Listener не трогает объекты, фигура в зазоре наблюдений, M1-гвардейлы §28.
- **Не-цели:** монстры, оружие, complex AI, полный город до успешного M1, переписывание сюжета.
- **Предположения (не подтверждены отдельно):** суммарно 3–4 часа; ночи ~20–30 мин; дни ~15–20;
  суд — единственный интерактивный «диалог ключом».

## 4. Секция 1 — Лентопишущий регистр (tape register)

Историческая основа: регистр Морзе (1837→1890s) — аппарат, пробивающий чернилами
точки-тире приходящего сигнала на бумажной ленте. На станциях хранился для разбора споров:
объективная запись против показаний оператора. Пишет непрерывно, пока линия под напряжением.

### Физически

Аппарат у ключа (не в зоне окна/двери): барабан, чернильное перо, лоток, короб.
Лента ~2 см, тянется горизонтально, к утру рулон в коробе — шесть дней бумаги к суду.

### Архитектура (решение 10)

`MorseRuntimeScheduler` эмитит `timing_event_started(MorseScheduledEvent)`.
Саундер — один подписчик. **Лента — второй:**

```
MorseScheduledEvent (MARK/GAP, duration_units)
    ├── SounderController → клик-клак (звук)
    └── TapeRegisterController → перо бьёт чернила (визуально)
```

- MARK → чернильная метка; длина ∝ units (точка короткая, тире длинное)
- GAP → лента ползёт без метки
- Тот же `advance_time`, что у саундера: один клок, ноль рассинхрона
- Пишет всё: трафик, служебные повторы, шум, стук в закрытую линию, двойную передачу
- **Не имеет доступа к тексту вообще** — только MARK/GAP. Лгать нечем (GDD §3.1 по построению)

### Чтение = интеракция

- Лента в лотке — `Interactable`: E поднимает полосу к лампе (расширение document_viewer)
- Прокрутка по длине ночи; лента накапливает всю смену
- **Никакого автокомпаратора с листом.** Сверка — работа игрока (GDD §5)

### Граница честности

Шум, съевший MARK, оставляет на ленте разрыв: видимый, не интерпретированный.
Audio fairness не нарушается: критическое морзе остаётся читаемым на слух всегда.

## 5. Секция 2 — Структура ночи и директивы

### Ночь как поток

State machine остаётся в коде (рабочая лошадка тестов). Ощущение ночи — поток:

- Линия как погода: трафик волнами, пауза может затянуться (тишина — оружие)
- Прерывания по этикету: служебная передача может перебить контентную (BK-break);
  лента пробивает обрыв середины слова как есть
- Смена дышит плотностью: пусто → очередь → паника накопившегося в конце

### Категории передач

1. **Служебный трафик** (1–3/ночь): подтверждения, маршрутные запросы, «переговоры точкой».
   Без расхождений.
2. **Контентные** (1–2/ночь): сюжет, директивы, расхождения, нити страха.
3. **Фоновый шум линии**: статика/дребезг/одиночные клики. Не сценарии. Лента пробивает
   обрывки. Никогда не расшифровывается. Ночь 3+ их больше.

### Директивы (Papers, Please)

Утром, до смены. Доставка α (решение 4): конверт в мире + директивная передача по морзе
первой в смену (дубль для подстраховки). В M1 — конверт на столе; в M2 — дневная сцена.

- Ночь 1: базовая процедура (обучение)
- Ночь 2: «код маршрута ХХ — в отдельную графу ledger»
- Ночь 3: «слова вида W___R — немедленно запросить подтверждение отправителя»
- Ночь 4: «при буре приём приоритетнее точности» (легализует расхождения)
- Ночь 5: «все расхождения — старшему оператору главной станции»
- Ночь 6: отмена компании / «оставь при себе» от отправителя доверия

Директива = `.tres` (расширение TelegraphScenarioData): текст, условие проверки, эффект на ledger.
Невыполнение — не fail, а цитация. Выполнение фиксируется: компании виден лояльный оператор.

### Типовой ритм (пример, ночь 3)

```
19:00 открытие линии, лента поползла
19:10 служебный трафик
19:25 контентная #1 (директива загружена в голову)
19:50 долгая тишина (лента ползёт пустая)
20:15 WATER → рука пишет WATCHER
20:16..grace дедлайн коммита
20:40 служебный трафик
21:30 одиночный стук в закрытую линию — лента пробила
23:00 closing signal, лента останавливается
```

## 6. Секция 3 — Экономика выговоров (b_c)

### Один ресурс: ledger смены

`dispatch_ledger` расширяется до **запись = событие смены**:

- **COMMIT** — отправлено (есть)
- **CITATION** — выговор: «КОПИЯ НЕ СООТВЕТСТВУЕТ РЕГИСТРУ — ст. 7, наряд №44».
  Пишется рукой Элиаса: соучастие — твоя рука фиксирует твою вину
- **DIRECTIVE-ACK** — директива получена/исполнена
- **REPEAT / BREAK** — служебные события линии (материал для суда)

### Тройной эффект цитации

1. **Наказание:** счётчик в WorldState. К ночи 5–6 режет доверие: поздние опции
   (продлить grace, доступ к архиву станции) недоступны. Не убивает.
2. **Улика:** формулировка выговора — документ давления. 3+ цитаций открывают ветку
   «шкала давления»: журнал с выговорами как свидетельство комиссии — «вот чем заставляли спешить».
   Ошибки игрока конвертируются в доказательство. Ничего не теряется (замечание владельца учтено).
3. **Психика:** ночь 4+ — при перечитывании ledger формулировка, которой не писал (нить руки, раз за игру).

### Грубые нарушения → аннулирование вечера (c)

Только за **бросание работы**, не за невнимательность:

- Ушёл от ключа при открытой линии на срок >> grace → служебная телеграмма
  «оператор отсутствует» → смена аннулирована, наряд переписан, вечер заново
- Деза в критической передаче без проверки по ленте при обязательной директиве →
  не рестарт, а тяжёлая цитата + испорченная улика уходит в мир

Граница чёткая: невнимательность = цитата; бросание = аннулирование.

### Проверяемость

Всё — факты WorldState/KnowledgeState + `.tres`. Тесты: цитация при X, счётчик режет Y,
аннулирование только при Z.

## 7. Секция 4 — Воскресный суд (интерактивный финал)

Воскресенье, 8:00. Линия мертва всю ночь — впервые лента ползла пустая. Главная станция
собирает конференцию 1894: комиссия штата, федеральный аудитор, компания — каждая на своём
ключе, диспетчер раздаёт очередь.

### Ход суда

1. **Зачитка по регистру.** Диспетчер читает ленту вслух, механически, точка за точкой:
   «что было передано на станции Блэк-Крик, вторник, 20:15». Напротив — твой лист и ledger.
   Всё, что прятал, читается машиной.
2. **Вопросы ключом.** Каждый вопрос комиссии — морзе. Ответы диегетические:
   - **ПОДТВЕРДИТЬ** — передать дословно по ленте
   - **ОТРИЦАТЬ** — настоять на своей записи против ленты
   - **МОЛЧАНИЕ** — не отвечать; диспетчер фиксирует: «станция Блэк-Крик не отвечает»
   - **ВСКРЫТЬ УЛИКУ** — передать собранное доказательство (если цепочка §17 достаточна)
3. **Тайминг реален.** На ответ — пауза этикета ~15–20 с. Промолчал дольше = отказ.
4. **Компания перебивает.** На неудобном — BK-врезка «возражение, станция не уполномочена».
   **После третьего возражения аудитор урезает линию компании.** Дальше — тишина,
   в которой отвечать придётся тебе.

### Что решает

Суд ничего не создаёт — **проявляет** собранное:

- Доказательная база определяет, какие вопросы прозвучат и чем грозит ОТРИЦАНИЕ против ленты
- 3+ цитаций: ветка «давление» открыта, но компания оспаривает компетентность
- Центральный момент: зачитка WATER, лист говорит WATCHER, диспетчер спрашивает
  «что записала станция?» — выбор при всех

Финалы GDD §18 = какие ответы даны в этом эфире и что вскрыто.
Send Nothing = систематическое молчание.

### После суда

Лента останавливается. Последнее на ней — твоя собственная передача.
Финальный кадр: короб с шестью днями бумаги. Всё записано, ничего не стёрто.

### Технически

- Суд = специализированный сценарий в `.tres`: вопросы/директивы диспетчера — данные
- Режим передачи ключа (уже нужен для повторных запросов ночи 3+) переиспользуется
- Нового UI нет: лента (чтение), лист (написание), ledger (зачитка) — три построенных документа
  и есть сцена суда

## 8. Секция 5 — Нити страха по ночам

Обе нити (решение 9). Никогда в одной передаче.

| Ночь | РУКА (психика) | ПРОВОД (линия) | Директива | Умение к концу ночи |
|---|---|---|---|---|
| 1 | рука надёжна, темп чистый | обычный трафик, рутина | базовая процедура | лист, коммит, сверка лентой; **первая ошибка — своя, понятая** (тренировочное расхождение на некритичной передаче) |
| 2 | микро-запинка: пауза пера +0.4 с на одной букве | буря съедает некритичную букву; на ленте разрыв | код ХХ в отдельную графу | чувствовать темп своей руки; потеря буквы без паники |
| 3 | **WATER→WATCHER** (защищённый момент) | стук в закрытую линию; лента пробила; записка «не отвечай» | W___R → запросить подтверждение | проверить лентой то, что сказала рука |
| 4 | дрожь руки; архивный лист не там; формулировка в ledger, которой не писал (раз за игру) | двойная передача поверх входящего (раз за игру, без объяснения) | при буре приём приоритетнее точности | проверять всё; сомнение в собственной памяти |
| 5 | игрок проверяет каждый лист лентой; Элиас — подозреваемый | «кто передавал? это не наша станция» — последствия по проводу | расхождения — старшему оператору | проверка выходит в мир; шкала цитаций |
| 6 | рука пишет то, чего в эфире не было: лента пустая, буквы появляются | финальная передача: имя Элиаса третьим лицом | отмена компании / «оставь при себе» | финальный выбор с полным знанием |
| Вс | рука на ключе суда | суд в реальном времени; компания урезана после 3-го возражения | — | финалы §18 |

### Правила включения

- Одно событие руки за ночь максимум (кроме ночей 3, 6 — там сюжетные пары). Sparse horror §3.5
- Провод-события пробивают ленту всегда, даже необъяснимые. Двойная передача ночи 4 на ленте —
  два наложения точек друг на друга: видно физически, понимания нет
- Фигура в окне — вне таблицы (решение 12): свой контракт, не доказательство
- Ночь 1 обязана быть чистой по страху: ноль аномалий, обучение + одна понятная ошибка.
  Доверие, которое потом предадим

### Мостики в код

- Запинки/дрожь = authored-вариации таймингов WriterRig (аномалия = отклонение от выученного
  темпа; контрактная база: `glyph_motion_duration`, `row_change_duration`)
- Стук/двойная передача = scheduler-события вне сценариев; лента их рендерит
- «Не наша станция» = контентная передача, ветвящаяся от фактов коммитов в KnowledgeState
- Пустая лента с буквами на листе = ночь 6: `written_transcript` без true-таймлайна.
  Слои §3.1 не схлопываются — это расхождение и есть сцена

## 9. Защищённые моменты (не нарушать)

- Лента никогда не искажается — единственный несокрушимый якорь
- Критическое морзе читаемо всегда (audio fairness §7); шум ест только некритичное
- Никаких стингеров/хушей на критическом письме (living-shift-plan, protected moments)
- Фигура — в зазоре наблюдений, никогда прямо, не награда, не доказательство
- Listener не трогает объекты (§10): любой физический сдвиг имеет другое объяснение
- Суд не наказывает — фиксирует. Наказание = то, что игрок уже сам записал
- Не строить: монстров, оружие, complex AI, город до успешного M1 (§28)

## 10. Порядок реализации (предложение, не mandate)

1. **Лента-регистр, M1-масштаб**: TapeRegisterController (второй подписчик scheduler),
   лента-Interactable, чтение в viewer. Тесты red→green по контракту «лента = MARK/GAP,
   не имеет доступа к тексту»
2. **night_index + конверт директив**: WorldState, `.tres`-директивы, инспект конверта
3. **Экономика цитаций**: типы записей ledger, счётчик, аннулирование вечера
4. **Контент ночей 1–2** (обучение + первая запинка/буря) — плейтест до ночи 3
5. **Ночь 3**: WATER→WATCHER + стук + записка (нить провода и руки сходятся)
6. Ночи 4–6, день (M2), суд

Каждый шаг — маленькие тестируемые системы (GDD §29), ничего вперёд M1-успеха.
