# WS5 — M1.5: ночи 2–3, директивы, цитации, прототип передачи

**Цель:** три ночи подряд из данных; хук WATER→WATCHER переезжает в ночь 3 (как в horror layer §8), ночь 1
становится чистым обучением с одной **своей** ошибкой; первая проверка глагола «передать ключом».

**Зависит от:** WS2 (вердикт плейтеста: петля держит), WS4 (NightData, WireService, глифы).
**Стоп-правило (GDD §28):** если плейтест WS2.12 провалил гейты — WS5 не начинать, чинить петлю.

**Источник дизайна:** `docs/design/DEAD_WIRE_HORROR_LAYER_DESIGN.md` §5 (директивы, ритм ночи), §6 (цитации),
§8 (нити страха по ночам). Не придумывать новые нити — брать из таблицы §8.

  константы в одном месте (`scripts/state/fact_ids.gd`, создать при первом новом факте).

### Task 5.1 — `night_index` и последовательность ночей

**Files:** `scripts/night/night_sequence.gd` (`class_name NightSequence extends Resource`,
`@export var nights: Array[NightData]`), `data/nights/campaign.tres`, `m1_office_controller.gd` (берёт ночь по
индексу из `user://save.json` → `{"night_index": N, "world": {...}, "knowledge": {...}}`).
Сохранение — только между ночами (после `DawnRitual`), не посреди смены (GDD §12: без перезагрузок).
**RED:** `night_sequence_test.gd` — после сохранения ночи 1 загрузка офиса поднимает ночь 2; сторы
восстановлены раздельно (два ключа, не один словарь).
**Commit:** `feat: nights run in sequence from data, saved between watches`

### Task 5.2 — Конверт директивы

**Дизайн (horror §5, решение α):** конверт на столе в начале смены + директива первой передачей по проводу.
**Files:** `scripts/night/directive_data.gd` (`text`, `check_id: StringName`, `ledger_line`), поле
`NightData.directive`; интерактив `DirectiveEnvelope` на столе (открыть → вьюер, `DocumentRouter`).
**Проверка директивы** — функция по `check_id` в `scripts/night/directive_checks.gd`, `match` на 2–3 случая
(не фреймворк). Ночь 2: «код маршрута в отдельную графу ledger». Ночь 3: «слова вида W___R — запросить
подтверждение» (связка с 5.6).
**RED:** `directive_test.gd` — ночь 2, маршрут без графы → факт `directive_missed`; с графой → `directive_kept`.

### Task 5.3 — Цитации в ledger

**Files:** `dispatch_ledger.gd` — строки типа `COMMIT / CITATION / DIRECTIVE_ACK / REPEAT` из сторов.
Цитация пишется **рукой Элиаса** (шрифт Cedarville, через тот же `WriterRig`, если игрок сидит; иначе — готовая
строка при следующем открытии). Счётчик `citations` в `WorldStateStore`.
**Правила (horror §6):** невнимательность = цитата; бросание ключа при открытой линии ≫ grace = аннулирование
вечера (ночь переигрывается с начала, ledger хранит строку «наряд переписан»).
**RED:** три теста — цитата при X, аннулирование только при Z, счётчик растёт монотонно.
**Commit:** `feat: citations land in the ledger in Elias's own hand`

### Task 5.4 — Ночь 1 (кампанийная) — чисто

`data/nights/night_1.tres`: 3 сценария без аномалий; фигуры нет; **одна своя ошибка** на некритичной передаче
(рука пишет верно, но игрок сам может ошибиться в маршруте — вторая передача с Rule 44 из WS2.5). Служебное
сообщение ночи: `WX FAIR CR` — **одно и то же каждую ночь** (research: ухо ловит дрейф в знакомом).
**Acceptance:** прохождение ночи 1 не содержит фактов `*_anomaly_*`; M1-ночь (`night_m1.tres`) остаётся как
демо-срез и не удаляется.

### Task 5.5 — Ночь 2 — давление внимания

`data/nights/night_2.tres` по §8: микро-запинка пера +0.4 с на одной букве (параметр в `written_transcript`
тайминге, не в `true_message`); буря съедает **некритичную** букву (флаг `critical_copy = false`, WS1.5); на ленте
разрыв; директива «код в графу». Служебное `WX FAIR CR` приходит как `WX FAIR CR` — пока без дрейфа.
Фигура — один раз, в зазоре (правила WS1.7 не меняются).
**RED:** `audio_fairness_test` расширить: в ночи 2 шум никогда не накрывает MARK сценария с `critical_copy = true`.

### Task 5.6 — Ночь 3 — противоречие (хук переезжает сюда)

`data/nights/night_3.tres`: сценарий `core_hook_water_watcher` из M1 (с решениями WS2.1–2.3); стук в закрытую
линию после `GN` (лента пробивает, WireService SERVICE-приоритет, текста нет — только MARK-кластер); записка
«не отвечай» — **предмет** появляется между наблюдениями, объяснение физическое (подсунута под дверь: звук
шагов на лестнице до этого, WS1.6-правило шагов). Директива W___R → игрок должен **запросить повтор**
ключом (5.7). Служебное сообщение дрейфует: `WX FAIR CR` → на ленте `WX FAIR CR`, рука пишет `WX FAIR CA`.
**Acceptance:** все инварианты §AGENTS; фигура и стук — не в одной передаче (horror §8 «никогда в одной передаче»).

### Task 5.7 — Прототип передачи ключом (GDD §36.2)

**Минимум:** игрок отбивает короткий запрос `RPT` (повтор) — 3 буквы. Ключ уже есть (`TelegraphKey`).
- Декодер отбитого: длительность нажатий → MARK точка/тире по порогу (порог = 2 юнита текущего профиля,
  ручка калибровки в `m1_morse_playback_profile.tres` — `send_threshold_units`).
- Отбитое идёт в планировщик → на ленту (регистр пишет своё как любое другое).
- Подсказка новичку: карточка на стене показывает `R P T`; после 2 неудач Элиас «передаёт сам» (запасной путь
  из рисков STATE §4) — факт `elias_sent_for_operator`.
**RED:** `key_sending_test.gd` — последовательность нажатий `.-. .--. -` при профиле M1 → `"RPT"`; дрожь ±25%
длительности всё ещё декодируется; лента содержит ровно эти MARK.
**Acceptance:** 3 из 5 плейтестеров отбивают RPT за ≤2 попытки. Иначе — упростить (одна буква `R`).
**Commit:** `feat: prototype — the operator can key a repeat request`

### Task 5.8 — Исследовательские приёмы (из production-value pass)

Для каждой ночи 2–3 проверить, использован ли хотя бы один:
1. одно и то же служебное сообщение каждую ночь (5.4–5.6);
2. соучастие собственной подписью — цитация рукой Элиаса (5.3);
3. правда запаздывает — слабая пружина держит хвост ленты (WS2.7);
4. тишина как оружие — одна пауза ночи дольше ожидаемой без события.
