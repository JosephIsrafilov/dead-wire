# План исправления руки — 2026-10-09

## Неудача предыдущей версии

Отвергнуто владельцем. Проверка соединённости узлов была недостаточна: верхний рукав
растягивался между неподвижным плечом и произвольным локтем. Длины костей не проверялись.
При диагностике обнаружена и отдельная ошибка генератора: запись по пустым строкам
переносит свойства между блоками scene и удаляет Nib/Shaft offsets при повторе.
Сцена на старте этой задачи действительно содержит Nib.position=(0,0,0), чего быть не должно.
Это нужно исправить до любых новых оценок. Предыдущие green не подтверждают текущую сцену.

## Рабочее решение

1. Сохранить отвергнутые файлы отдельно. Восстановить точные смещения пера из сохранённой
   сцены, не откатывая чтение/ходьбу/музыку. Заменить запись свойств по пустым строкам на
   запись строго внутри одного node block. Проверить два последовательных rebuild SHA256.
2. Зафиксировать одну сидячую позу с небольшим наклоном корпуса к столу. Плечо в sheet-local
   (0.07,0.17,0.57), плечо–локоть 0.30 м, локоть–манжета 0.27 м. Это авторская поза,
   не камера-зависимый трюк. Плечо не вращается вместе с мышью. Контакты бумаги не меняются.
3. Заменить вращение всего длинного рукава на аналитическую двухзвенную цепь с постоянными
   длинами и фиксированным направлением сгиба локтя наружу/слегка вниз. Кисть с пером остаётся
   жёсткой сборкой; nib всегда достигает глифа. Манжета соединяет эту сборку с предплечьем.
   Сегменты имеют нормальные толщины, без растяжения за буквой. Небольшое перекрытие ткани
   у локтя скрывает только шов двух частей, а не ошибку положения суставов.
4. RED: Nib offset и Pen parenting, костные длины/плечо/стыки/скейл, обе строки,
   entry/withdraw/suspend/reset. Не ослаблять тесты 44/2008; новые тесты добавляют требования.
5. Оконный Godot: одинаковые seated/desk/side/top кадры и последовательность движения
   с пером на первом/последнем глифе, переходе строки, убирании. Сначала смотреть силуэт,
   манжету и длину предплечья, потом тесты. Не называть пальцы принятыми: это отдельная
   нерешённая задача, не маскировать её тёмной тканью/светом.
6. Полная регрессия, lint, boot и production route. Документировать ограничения честно.

## Инструменты

Проверены доступные MCP resources/templates: 3D/Blender коннектора нет. Для двухзвенной
цепи Godot Vector3/Basis и ArrayMesh достаточно; установка MCP не исправляет неправильную
анатомию и не нужна на критическом пути. Если потребуется внешняя skinned-модель кисти,
это следующий этап с подтверждённой лицензией и отдельным исходником, не случайный пакет.
Blender не установлен. Ничего внешнего пока не устанавливается, порт с выполнением кода
не открывается. Никакого commit/push. Старые меши сохраняются в резервной копии.

## Критерии

- Сегменты 300/270 мм в каждом кадре (допуск <0.1 мм); ни scale drift, ни резиновая рука.
- Плечо не уезжает, локоть на одной стороне, манжета/перо не разъезжаются.
- Ниб <1 мм от контакта, один glyph_contact на одну букву, без новых букв при reset.
- Окно и стол не переставляются ради руки. Освещение не меняется.
- Силуэт должен выглядеть как согнутая правая рука сидящего человека, не трубка до камеры.
- Финальная художественная приёмка остаётся за владельцем, не за assert.
